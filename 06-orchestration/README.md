# 第 6 章：编排层选型与接入

状态：规划中，尚无可运行实现。按章学习，本章不提前完成真实双 CLI 系统。

## Workflow 目标

区分智能协调、执行编排与验收控制，优先复用已有编排工具。Hermes、Pi 等是候选；只有验证过的能力才进入依赖清单。最终只选择一个满足本阶段需求的工具，不同时实现多个框架适配。

## 选型实验

1. 在实现本章时查阅官方资料并固定候选版本、许可证、运行环境与接口。
2. 检查候选负责什么：任务建议、CLI 委派、会话管理、输出传递、取消或恢复；不把不同职责混为一谈。
3. 比较依赖、权限边界、账号要求、维护成本及 Rust 对接方式。
4. 用候选工具委派一次无源码写入的模拟任务，返回可校验的任务 ID 和结果。
5. 记录选型结论、已验证能力、缺口以及复用与自建的责任边界。

Pi 或 Hermes 的具体能力将在本章实现时核对；必要时比较专门的 CLI 编排工具。若候选需要额外推理入口，应明确是否符合项目的 CLI-only 约束，不默认扩大约束。

## 验收计划

- 一次模拟委派能够完成，结果能关联原任务。
- 错误或空结果不能被当作成功；职责和依赖有明确记录。
- 不实现通用编排引擎，不要求本章支持完整修复、生产隔离或崩溃恢复。
- 后续通过受控执行与恢复章节补齐并验证缺口，不能因采用框架省略门禁。

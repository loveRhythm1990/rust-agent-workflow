# 第 2 章：任务契约与验收标准

状态：已实现文本契约校验与版本比较。本章不执行编码、模型调用或实际验收。

## 为什么先写任务契约

“增加问候功能”不足以判断完成。我们需要明确改哪里、不能做什么、怎样观察成功，以及什么情况算失败。契约是用户和实现者共同确认的任务边界，不是 Agent 自己生成的完成声明。

本章将契约写为 UTF-8 文本：每行一个字段，使用英文冒号；不支持多行字段。空行和字段周围空白允许存在，未知字段、重复字段及空值会被拒绝。

## 契约字段

| 字段 | 含义 |
| --- | --- |
| 版本 | 从 1 开始的整数，业务内容变化时加一 |
| 目标 | 要实现的可观察行为 |
| 范围 | 允许修改的文件或模块 |
| 非目标 | 本次明确不实现的内容 |
| 约束 | 兼容性、依赖及其他限制 |
| 验收操作 | 在什么位置执行什么操作 |
| 预期结果 | 可检查的具体输出或行为 |
| 反例 | 哪种行为应判为不通过 |

[完整示例](examples/task.txt)只描述一个待实现任务：保持现有输出，并在末尾打印“任务已接收”。其中的 `cargo run` 是任务的验收说明，本章仅将其作为文本保存，不执行它。目标环境、资源与更完整的验收矩阵将在后续章节扩展。

## 运行实验

以下命令都从仓库根目录运行。无需第三方依赖或模型账号。

```bash
cargo run -p chapter-02-contracts
```

不传路径时读取内嵌的完整示例，输出“输入门禁通过”，显示契约，并提醒业务含义仍需人工确认。

### 实验一：拒绝缺失预期结果

```bash
cargo run -p chapter-02-contracts -- 02-contracts/examples/missing.txt
```

预期：标准错误输出包含 `字段“预期结果”不能为空`，程序退出码为 1。只写验收操作、没有预期结果，不能进入实施。

### 实验二：比较修订版本

```bash
cargo run -p chapter-02-contracts -- 02-contracts/examples/revised.txt 02-contracts/examples/task.txt
```

参数依次是当前契约、上一版契约。示例将输出改为“任务已登记”，版本从 1 改为 2，比较通过。

复制 revised.txt 到临时文件，将版本改回 1，再用同一命令替换当前路径：应被拒绝。仅更改冒号周围空白不算业务变化，不应提升版本。

单独校验一份契约只能检查版本是合法正整数；要检查是否正确递增，必须提供上一版。程序不改写或覆盖契约文件，也不持久化版本历史。

### 实验三：读取失败

```bash
cargo run -p chapter-02-contracts -- 02-contracts/examples/not-found.txt
```

预期：显示读取失败，退出码为 2；不会伪装成有效契约。

## 实现结构

- [src/main.rs](src/main.rs)：读取参数和文本，打印结果，设置退出码。
- [src/lib.rs](src/lib.rs)：校验必填字段与修订版本，包含自动化测试。
- `examples/`：完整、缺失字段和修订契约。

核心接口 `validate_contract(&str)` 借用文本，返回问题列表；列表为空表示格式门禁通过。`validate_revision(&str, &str)` 校验两份契约后比较字段。正式任务类型、运行记录与 JSON 模型留到第三章。

## 门禁的真实边界

通过只代表字段齐全、格式有效、提供上一版时版本关系正确。`预期结果: 看起来不错` 也可能通过格式检查，但业务标准不充分，需要人工修订。本章无法自动发现需求冲突，也不执行范围限制或证明实现正确。

验收依据应先确认，再交给编码者。业务歧义由用户澄清；实现者不能为让结果通过而自行弱化预期。版本变化意味着旧验收结论不能直接用于新契约，证据失效机制在后续实现。

## 验证与完成标准

```bash
cargo test -p chapter-02-contracts
cargo check --workspace
cargo fmt --all --check
```

测试覆盖空值、缺失、重复、未知字段、非法版本、修改未升版、正确升版、跳号、排版变化及版本溢出。

完成本章后，你应能写出有操作和具体预期的契约，运行三个实验，并说明“输入门禁通过”为什么不同于“任务验收通过”。

## 动手练习

1. 新建一个契约文件，描述你想实现的简单命令行功能，先通过格式门禁。
2. 将预期改成模糊描述，观察程序仍可通过，练习人工补充可观察标准。
3. 修改一条约束，先不升版观察拒绝，再升版重试。
